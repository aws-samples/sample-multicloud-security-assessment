# Post-Scan Security Assessment Inference

> **Analyze Prowler scan outputs and generate comprehensive customer-facing deliverables — interactive dashboard, executive deck, remediation plan, and IaC scripts.**

## Overview

After running a multicloud security assessment with this solution, the **inference skill** processes the Prowler output and generates a complete set of customer-ready artifacts:

- 📊 **Interactive HTML dashboard** — KPI cards, security-score gauge, severity/service charts (Highcharts), findings tables, remediation cards, and a phased roadmap
- 📑 **AWS-branded PowerPoint deck** (11 slides) — executive summary, findings, remediation, roadmap
- 📄 **Phased remediation plan** (PDF) — Day 1-3, Week 1-2, Month 1, Ongoing
- 🛠️ **IaC remediation scripts** — CloudFormation *or* Terraform (your choice, never mixed)
- 📘 **README** tying the deliverables together with deploy/rollback instructions

## How It Works

Given a folder of Prowler output (generated by this solution's CodeBuild scans), the skill:

1. **Scans** the output folder and identifies assessment files (main CSVs, compliance CSVs, OCSF JSON, HTML)
2. **Parses** findings from semicolon-delimited Prowler CSVs — severity, service, compliance mapping, remediation code
3. **Computes** a security score `(pass / total) × 100` and groups findings by severity and service
4. **Generates** the dashboard, executive deck, IaC remediation scripts, README, and PDF plan
5. **Optionally anonymizes** AWS account IDs for customer distribution

## Requirements

- **Amazon Quick** desktop app ([request access](https://w.amazon.com/bin/view/Amazon_Quick))
- Prowler output files from this solution (CSV / JSON / HTML from the S3 results bucket)

## Install

Copy the `inference/` folder into your Amazon Quick skills directory:

```bash
# macOS / Linux — replace <profile> with your Quick profile name
cp -R inference/ ~/.quickwork/profiles/<profile>/skills/resco-security-inference/
```

Restart Amazon Quick (or reload skills) and the skill will appear.

## Usage

In Amazon Quick, trigger the skill with any of:

- "resco security inference"
- "external security assessment"
- "customer-facing security assessment"
- "security assessment for customer"

The skill will prompt you for:

| Input | Description |
|-------|-------------|
| Input folder | Path to Prowler output (downloaded from the solution's S3 bucket) |
| Output folder | Where to save generated deliverables |
| Customer name | Auto-detected from filenames if possible |
| IaC format | CloudFormation **or** Terraform (all one format) |
| Remediations | Which security controls to generate IaC for |
| Anonymize? | Whether to mask AWS account IDs in customer outputs |

## Workflow Integration

This skill fits into the overall solution workflow as the final reporting step:

```
┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐    ┌─────────────────┐
│ Deploy Solution │───▶│ Run Prowler     │───▶│ Download Output │───▶│ Run Inference   │
│ (CloudFormation)│    │ (CodeBuild)     │    │ (S3 Bucket)     │    │ (This Skill)    │
└─────────────────┘    └─────────────────┘    └─────────────────┘    └─────────────────┘
```

1. Deploy the appropriate CloudFormation template from `aws/`, `azure/`, `gcp/`, or `oci/`
2. Run the CodeBuild project to execute the Prowler scan
3. Download the results from the S3 output bucket
4. Run this inference skill against the downloaded output to generate customer deliverables

## Supported Input Formats

| File Type | Description |
|-----------|-------------|
| Prowler main CSV | Semicolon-delimited, columns: STATUS, SEVERITY, CHECK_ID, SERVICE_NAME, etc. |
| Prowler compliance CSV | Framework-specific checks (in `compliance/` subfolder) |
| Prowler HTML | Visual scan reports |
| Prowler OCSF JSON | Open Cybersecurity Schema Framework output |
| Security Hub JSON | AWS Security Hub finding exports |

## Generated Remediations (IaC)

The skill can generate production-ready IaC templates for common security findings:

| Remediation | Description |
|-------------|-------------|
| S3 Block Public Access | Account-level block + default encryption |
| IAM MFA Enforcement | Deny policy without MFA present |
| Security Group Restriction | No unrestricted ingress on sensitive ports |
| EBS/RDS Encryption | Default encryption at rest |
| CloudTrail Multi-Region | Trail with log validation in all regions |
| VPC Flow Logs | Network visibility via CloudWatch Logs |
| KMS Key Rotation | Automatic annual rotation monitoring |
| Access Logging | S3 + ALB access log enablement |

All scripts follow AWS best practices: least-privilege IAM, parameterized values, tagging, outputs, and rollback instructions.

## Key Technical Notes

- Prowler CSVs use **semicolons (`;`)** as delimiters — not commas
- Security score formula: `(PASS count / total checks) × 100`
- The PPTX deck uses `LAYOUT_16x9` (10" × 5.625") with AWS branding
- IaC format is always uniform (all CF or all TF, never mixed)
- Critical findings are always presented first in all deliverables
